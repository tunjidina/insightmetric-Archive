# Contributing

Thank you for considering a contribution. InsightMetric is a small project and the aim is to
keep it that way: clear, useful, and understandable to someone who is not a specialist.

## What we are looking for

Contributions are welcome in three areas:

**Interface improvements.** Clearer layouts, better labels, accessibility fixes, sensible
behaviour on small screens, anything that makes a page easier to read or use. This is the
most useful place to help.

**Documentation.** Corrections, clearer explanations, better examples. If something in
[USAGE.md](USAGE.md) confused you, that is a documentation bug and worth reporting — you are
the best possible witness to it.

**Feature suggestions.** Ideas for what the product should do next. A well-described
suggestion is a real contribution even without any code attached.

## Reporting a problem

Open an issue and include:

- **What you did** — the page you were on and what you clicked
- **What you expected**
- **What happened instead**
- **A screenshot**, if it is something visible
- **Your browser**, if the layout looks wrong

Small, specific reports are more useful than long ones. "The recurrence badge overlaps the
topic title on a phone" is an excellent issue.

## Suggesting a feature

Open an issue describing:

- **The problem it solves.** Start here rather than with the solution — the problem is the
  part worth discussing, and there is often a simpler answer than the one first imagined.
- **Who it helps**, and when they would use it.
- **What it would look like.** A rough sketch or a description of the screen is plenty.

Suggestions that make the product simpler are as welcome as ones that add to it.

## Submitting a change

1. Fork the repository and create a branch.
2. Make your change, keeping it focused — one improvement per pull request reviews far
   faster than several bundled together.
3. Open a pull request describing what changed and why. Include a before-and-after
   screenshot for anything visual.

The `main` branch is protected, so all changes arrive through pull requests. Please be
patient with review; this is a side project and responses may take a few days.

## Scope

Some parts of the project are not open for contribution, and it is only fair to say so
before anyone spends an evening on them. The internal design — how the product gathers,
processes and estimates — is maintained privately and is not documented publicly. Pull
requests that reach into those areas will be declined regardless of quality, which is a
waste of your time and an awkward conversation for both of us.

If you are unsure whether an idea falls inside or outside that line, **open an issue and
ask first.** A one-line question saves a wasted weekend.

## Conduct

Be straightforward and be kind. Assume the person you are replying to is acting in good
faith and knows things you do not. Criticism of an idea is welcome; criticism of a person is
not.
